## Текст (правится здесь, и только здесь)

Ниже — сам текст. Он читается сборкой ИЗ ЭТОГО ФАЙЛА (первый блок в
тройных кавычках), так что замена страницы — правка данных, а не кода:
поправить строки → `python3 tools/build_port_rom.py` → гейт.

```
SPIRITS

принцессу и проклял паладина
Заклятие снимешь только ты!

УПРАВЛЕНИЕ:

жезлом - с принцессы.
3. Потом бей орла молнией. Но
не касайся его - это смерть!
4. Молния лишь глушит и ест
силу. Рычаги открывают проход.
```

Ряды: после сжатия блока управления (одна строка «Стрелки - Перемещение»
вместо двух) свободен один ряд. Буквы `O`/`P`/`Q`/`A` на клавиатуре
Вектора в ход больше не идут — только стрелки и джойстик (раскладка
Вектора другая; решение владельца 2026-09-24).

ЗНАКИ ЭТОГО ТЕКСТА ПРОВЕРЕНЫ ПО ОБРАЗУ: всё, кроме букв, цифр, `:` и
пробела (`. , - / ! ( ) =`), берётся из таблицы дорисованных; ничего
дорисовывать заново не пришлось. Из девяти дорисованных знаков новым
текстом НЕ ИСПОЛЬЗУЕТСЯ `*` (8 байт таблицы лежат про запас).

### Что сборка делает с этим текстом (и почему)

| правило | почему |
|---|---|
| строки из одних дефисов ВЫБРАСЫВАЮТСЯ (сейчас 0 штук) | их место заняла рамка по периметру — решение владельца 2026-09-22 |
| всё поднимается в ВЕРХНИЙ регистр (сейчас 315 знаков) | в шрифте игры строчных букв нет вообще (`docs/i18n-inventory.md` § 2.2) |
| первая строка — ЗАГОЛОВОК: **ряд 0, В ВЕРХНЕЙ СТРОКЕ РАМКИ**, по центру, БЕЛЫМ, с пробелом по бокам | решение владельца 2026-09-22; остальные строки идут с ряда 2 подряд |
| ПУСТЫЕ СТРОКИ ДАЮТ ПУСТЫЕ РЯДЫ, левый отступ строки сохраняется | и то, и другое — часть вёрстки владельца (разделы; `Стрелки`, `Space`, `1..5`) |

### Границы, за которые сборка не пустит

* ширина строки — **не больше 30 знакомест** (внутри рамки колонки 1..30);
* строк текста (без заголовка) — **не больше 21** (ряды 2..22), пустые
  строки считаются наравне с непустыми;
* знак, которого нет ни в шрифте игры, ни в списке дорисованных, роняет
  сборку с указанием самого знака.

Сейчас: заголовок + 20 строк тела (из них 2 пустых), ряды 2..21 из
2..22 — один ряд свободен.

## Кодировка: чем нарисован каждый знак

Кодировка — **шрифт самой игры**: те же коды, что печатает `2:CE36`, и
та же база (операнд `1737`, сейчас `9BE2`). Таблица «символ → код» одна на
проект — `tools/i18n_ru.py` (`CHAR_CODE`, `docs/i18n-ru.md` § 1).

В шрифте игры нет знаков препинания, кроме `:`, пробела и `%`. Девять
недостающих — `. , - * = / ! ( )` — **дорисованы в стиле шрифта** в
`tools/mk_help.py` (`PUNCT`) и лежат ОТДЕЛЬНОЙ таблицей рядом с текстом,
кодами `0xF0..0xF8`. Печатнику игры эти коды не видны, и ради них не
тронуты ни таблица глифов, ни два операнда базы (`1737`/`23FE`), то есть
образ адаптера остался ровно тем, который проверен гейтами перевода.

**Почему не переезд шрифта на `407E` (вариант A из `docs/gameplay.md`
§ 13.4).** Та оценка считала зону `407E..49FF` свободной целиком — 2434
байта. В слитом дереве это не так: `4400..461F` заняли списки объектов
`SPRL`/`SPRO`, `4620..` — заставка. Свободного осталось `407E..43FF`
(898 б) и `4775..49FF` (651 б), и переехавшая таблица (98 глифов = 784 б,
с девятью знаками препинания — 856 б) съедает первый кусок целиком,
оставляя потоку и коду только второй: 553 + 260 = 813 байт при 651. Не
влезает. Текущий раскрой (таблица шрифта НЕ трогается, знаки препинания —
свои) оставляет 273 свободных байта в первом куске и 412 во втором.

## Рамка

По периметру — **тот же орнамент, что у панели HUD**: коды глифов
`0x70`/`0x71` вперемежку (`docs/i18n-inventory.md` § 1.3 — в потоке панели
`9B56` они и образуют рамку), цветом пера панели, то есть кодом цвета 2
(плоскость `C000`). Правило чередования — чётность `(ряд + колонка)`.
Фигурки `0x57..0x66` — это ЖИЗНИ, а не рамка, и здесь не используются.

**ЗАГОЛОВОК ВРЕЗАН В ВЕРХНЮЮ СТРОКУ РАМКИ** (решение владельца
2026-09-22): в ряду 0 орнамент прерывается на девять знакомест по центру
(колонки 11..19), и там стоит « SPIRITS ». Ассемблер при этом НЕ ТРОНУТ:
`T_FRAME` по-прежнему кроет ряд 0 целиком, а поток поверх кладёт в
плоскость орнамента девять ПРОБЕЛОВ (глиф `0x73` шрифта игры — восемь
нулей, он и стирает орнамент) и уже поверх, в плоскость текста, сам
заголовок. Заголовок поэтому БЕЛЫЙ, а не цвета рамки, и стоило это одну
лишнюю запись потока — 10 байт данных, 0 байт кода.

Палитра страницы (`HELP_PAL` в `src/v06/title.asm`): код 0 — чёрный,
код 1 — белый (текст И ЗАГОЛОВОК), код 2 — `0x18` (рамка, тот же байт, что
стоит во втором слоте палитры комнаты).

## Формат потока (его читает `T_HELP`)

```
[флаги][колонка][длина][коды...]  ...  [0xFF]
флаги: биты 0..4 — ряд 0..23
       бит 7 = 1 — плоскость C000 (цвет 2), 0 — плоскость E000 (белый)
```

Рамки в потоке НЕТ: её рисует циклом сам `T_FRAME` по правилу чётности —
так она стоит 0 байт данных вместо 222. Для гейта те же знакоместа
пересчитывает заново `tools/mk_help.py`.

## Где лежит

| что | адреса | байт |
|---|---|---:|
| девять дорисованных знаков | `407E..40C5` | 72 |
| поток текста | `40C6..42F2` | 557 |
| **свободно до `SPRL` (4400)** | `42F3..43FF` | **269** |
| код заставки + справки | `4620..4878` | 601 (код 561, данные 40) |
| **дальше — не свобода, а экранный адаптер**: `MIRBUF` `4864..488B` (хвост заставки делит с ним место — они разведены во времени, `docs/v06-memory.md` § 8), таблицы `BKP` `488C..4969`, `MG_ZBUF` `4990..49B7` | `4879..49FF` | — |

`407E..43FF` — начало МЁРТВЫХ теневых таблиц спрайтов игры: этап E
выбросил обе чистки в `D0F2`, и за 3000 кадров код игры не прочитал и не
записал там ни байта (счётчик `SHADOW` в `tools/trap_stale_v06js.js`).
Поэтому текст жив всё время работы игры, а не только до старта.
